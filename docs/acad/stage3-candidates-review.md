## 검토 목적

쉼표(Swimpyo) MVP 아키텍처 스타일을 결정하기 전에, ASR(아키텍처 드라이버)을 기준으로 후보 3개를 비교 평가한 결과입니다. 팀과 상의 후 섹션 ②(최종 선택 + 트레이드오프) 진행 예정.

## 핵심 제약 재확인 (배경 정보)

- **팀**: 2명, 인프라 전담 없음 (AD-CON001)
- **일정**: MVP 2주 (AD-CON002)
- **프론트엔드**: Streamlit (AD-CON003)
- **호스팅**: Streamlit Cloud 무료 티어 (AD-CON004)
- **운영**: 대회 후 지속 운영, 인프라 비용 ≈ 0원 (AD-CON006)

## 핵심 P0 드라이버 (평가 기준)

- AD-A001 시연 2시간 무중단
- AD-A003 LLM 장애 시 핵심 기능 정상 + 폴백
- AD-S001 PII 영구 저장 0건
- AD-S002 LLM 호출 시 식별 정보 0건 전송

- AD-S006 익명 상담 PII 미수집 (조건부)
- AD-U001 셀프체크 30초 이내

## 후보 1: 모듈러 모놀리스 + 파일 기반 산출물 (단일 Streamlit 앱)

### 한 줄 정의
모든 런타임 컴포넌트를 단일 Streamlit 프로세스에 모듈로 묶고, ETL·학습은 별도 배치 스크립트로 실행해 결과물(모델 파일·전처리 데이터)을 파일로 공유하는 구조.

### 주요 컴포넌트
- 단일 Streamlit 앱 (관리자 대시보드 + 교사 셀프체크 + 챗봇이 페이지로 분리)
- 인메모리 모델 로딩 (XGBoost/LightGBM + SHAP 사전 계산)
- 외부 LLM 게이트웨이 모듈 (비식별화 + 폴백 + 응답 검증)
- 공공데이터 어댑터 + 통합 ETL (오프라인 배치)
- 산출물: 모델 pickle, Parquet/CSV, SHAP 값 사전계산, 학교 메타데이터

### 장점
- 2주 MVP에 가장 현실적, 학습 곡선 거의 없음
- 운영 복잡도 최소 (단일 프로세스), 팀 2명에 적합
- Streamlit Cloud 무료 티어에 직결
- 인메모리 모델로 What-if 시뮬레이션 빠름 (AD-P002 유리)
- 파일 산출물 교체로 모델 재학습 무중단(AD-F005·M001) 자연스럽게 달성

### 단점
- 단일 프로세스 → 한 모듈 장애 시 전체 영향 가능 (AD-A001 위협)
- 백그라운드 워커 어려움 → 데이터 갱신은 수동/외부 트리거
- 향후 트래픽 증가 시 분리 비용 발생 (AD-C001 P2)

## 후보 2: Streamlit + FastAPI 백엔드 분리 (분리 모놀리스)

### 한 줄 정의
프론트는 Streamlit, 모델 추론·LLM 게이트·SHAP 계산은 FastAPI 백엔드로 분리하여 두 프로세스로 나눈 구조.

### 주요 컴포넌트
- Streamlit 앱 (UI만)
- FastAPI 백엔드 (모델 추론 + LLM 호출 + 비식별화 게이트)
- 별도 배치 스크립트 (ETL·학습)

### 장점
- UI와 추론 로직 분리 → 각자 독립 배포 가능 (AD-M001 더 강함)
- 백엔드 장애와 UI 장애 격리 (AD-A003 잠재적으로 유리)
- 표준적이고 확장에 유리

### 단점
- **2주 MVP에 비현실적** — 두 서비스 운영, 호스팅·CORS·통신 디버깅 추가 부담
- **Streamlit Cloud 무료 티어로는 두 서비스 호스팅 어려움** → 별도 호스팅 필요 (AD-CON004·CON006 위반)
- 팀 2명에 운영 복잡도 부담 (AD-CON001 위반)
- UI ↔ 백엔드 호출이 추가 → What-if 1초 이내(AD-P002) 더 어려워짐

---

## 후보 3: Streamlit + 서버리스 함수 (하이브리드)

### 한 줄 정의
가벼운 UI·라이트 추론은 Streamlit, 무거운 작업(LLM 호출·PDF 생성·재학습)은 AWS Lambda/Cloud Functions로 분리하는 구조.

### 장점
- 무거운 작업의 자원 부담을 분산
- 사용량 기반 과금으로 비용 효율 가능성

### 단점
- **AD-CON004(Streamlit Cloud 무료 티어), AD-CON006(인프라 비용 ≈ 0원) 위반** — 클라우드 함수는 무료 티어가 있지만 운영·계정 관리 부담
- 콜드 스타트 → AD-P002·P003 위협 (1~2초 추론 ≈ Lambda 콜드 스타트와 비슷)
- 팀 2명·인프라 전담 없음에서 멀티 클라우드 운영 부담 (AD-CON001 위반)
- Streamlit ↔ Lambda 통신·인증·시크릿 관리 추가 학습 필요 (AD-CON002 위반)

## 비용·시간 검증 (AD-CON001·CON002 hard constraint)

| 후보 | 구현 기간 (2명 팀) | 운영 비용/월 | 비즈니스 임팩트 vs 복잡도 |
|------|--------------|----------|--------------------|
| **후보 1** | 2주 가능 (Streamlit 익숙도 가정) | 0원 (무료 티어) | 가장 단순, 비즈니스 목표 충족 가능 |
| **후보 2** | 3~4주 (분리·통합·디버깅) | 백엔드 호스팅 비용 발생 | 표준적이나 2주에 부적합 |
| **후보 3** | 3~4주 (서버리스 학습) | 함수 호출 비용 + Streamlit 유지 | 콜드 스타트 리스크 |

→ **후보 2·3은 hard constraint(2주·인프라 전담 없음·무료 호스팅) 위반으로 사실상 배제**

## 단순 대안 충분성 검토

> 단순 대안(후보 1)이 비즈니스 목표를 달성할 수 있는가?

- ✅ 50명 동시 접속 → Streamlit Cloud 무료 티어로 충분 (가정 A4 검증 필요)
- ✅ What-if 시뮬레이션 → 인메모리 모델로 충분, 외부 호출 없음
- ✅ LLM 안내·챗봇 → 외부 호출 + 폴백 패턴으로 충분
- ✅ 운영 무중단 갱신 → 파일 교체로 충분 (Streamlit Cloud 자동 재시작)
- ✅ MVP 후 지속 운영 → 비용 0원으로 가능

**결론**: 단순 대안으로 비즈니스 목표 달성 가능. 후보 2·3의 추가 복잡도를 정당화할 근거 부재.
